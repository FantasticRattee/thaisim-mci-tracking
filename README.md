# ThaiSIM MCI Tracking

เว็บทดลองติดตามผู้ป่วยในสถานการณ์จำลองสาธารณภัยหมู่ สำหรับบันทึกและดูการเคลื่อนย้ายผู้ป่วยระหว่างจุดปฏิบัติงาน

- เปิดเหตุการณ์ใหม่ ปิดเหตุการณ์เดิม และดูประวัติแยกตามเหตุ
- ลงทะเบียนเจ้าหน้าที่ครั้งแรกและกลับมาใช้ username เดิม พร้อมจำนวนเจ้าหน้าที่ออนไลน์ในเหตุการณ์
- ภาพรวมตามสีคัดแยกและรายงานเปรียบเทียบ Primary กับ Secondary
- แฟ้มผู้ป่วยและประวัติการอัปเดต พร้อมสัญญาณชีพ หัตถการ และปลายทางส่งต่อ
- พื้นที่ปฏิบัติงานและสถานะการชำระล้าง
- คลังเวชภัณฑ์แยกตามเหตุการณ์ หักจำนวนที่ใช้เมื่อบันทึกแฟ้มผู้ป่วย
- ดัชนีคู่มือสารเคมีพร้อมทางเข้า ERG4Thai สำหรับเว็บ, iOS และ Android
- การ์ด QR ที่แตะ คลิก หรือสแกนเพื่อเปิดแฟ้มเดียวกันตามเหตุการณ์และรหัสผู้ป่วย
- หน้าจัดการข้อมูลมีตารางผู้ป่วย เจ้าหน้าที่ และเหตุการณ์ บัญชีเดโมจัดการข้อมูลได้โดยตรง การลบผู้ป่วยนำออกจากรายชื่อประจำเหตุและเก็บประวัติไว้
- เมื่อทีมบันทึกข้อมูล เซิร์ฟเวอร์จะแจ้งหน้าที่เปิดอยู่ผ่าน Server-Sent Events และโหลดข้อมูลล่าสุดจาก SQLite อีกครั้งเมื่อกลับมาออนไลน์บนการ์ด

ข้อมูลเริ่มต้นเป็นข้อมูลสมมติสำหรับการฝึกซ้อม เจ้าหน้าที่เป็นผู้เลือกสีคัดแยกและบันทึกข้อมูลด้วยตนเอง ใช้ชื่อสมมติและเลี่ยงการกรอกข้อมูลผู้ป่วยจริง

## รันในเครื่อง

ติดตั้ง Node.js 22 แล้วรันคำสั่งต่อไปนี้

```sh
npm ci
cp .env.example .env
```

ตั้งค่าสุ่มสำหรับ `SESSION_SECRET` ใน `.env` แล้วเริ่มเว็บ

```sh
node --env-file=.env src/server.js
```

เปิด [localhost:3000](http://localhost:3000) แล้วคัดลอก `DemoThaiSIM001` จากโน้ตใต้ช่องชื่อผู้ใช้ หรือลงทะเบียนด้วยข้อมูลสมมติ ระบบนำชื่อเล่น สังกัด และสามตัวท้ายของรหัสบุคลากรมาต่อกัน หากระบุ `000` ระบบจะออกเลขสามหลักให้ ชื่อผู้ใช้รูปแบบเดิมยังเปิดบัญชีเดิมได้

```sh
npm test
```

## Deploy บน Railway

ใช้ Dockerfile ที่อยู่ใน repo ตั้ง `SESSION_SECRET` ใน Railway Variables สร้างโดเมนสำหรับเว็บ และผูก Volume ที่ `/data` เพื่อเก็บ SQLite เมื่อ redeploy ระบบใช้โดเมนของ Railway สร้างลิงก์บน QR หากใช้โดเมนอื่น ตั้ง `PUBLIC_ORIGIN` เป็น URL เต็มของเว็บ

เว็บไซต์มี endpoint `/healthz` สำหรับตรวจสอบว่าเซิร์ฟเวอร์พร้อมให้บริการ

## ข้อมูลใน SQLite

| ตาราง | ข้อมูลที่เก็บ |
|---|---|
| `incidents` | ชื่อเหตุการณ์ เวลาเปิด และเวลาปิด |
| `patients` และ `history` | แฟ้มปัจจุบันและประวัติการอัปเดต ผูกด้วยรหัสเหตุการณ์และรหัสผู้ป่วย |
| `staff_accounts` และ `staff_presence` | บัญชีเจ้าหน้าที่ตาม ID ถาวร และสัญญาณออนไลน์ล่าสุดตามเหตุการณ์ |
| `stock` และ `stock_movements` | ยอดคงเหลือแต่ละเหตุ และรายการที่หักในแต่ละแฟ้ม |

ตอนอัปเกรด ระบบจัดข้อมูลเดิมไว้ในเหตุการณ์ `legacy` และ QR เดิมยังเปิดแฟ้มในเหตุการณ์นี้ได้ บัญชีเจ้าหน้าที่เป็นข้อมูลร่วมของทุกเหตุการณ์ เจ้าหน้าที่ที่เคยลงชื่อก่อนอัปเกรดลงทะเบียน username ครั้งแรกได้จากหน้าเข้าสู่ระบบ
